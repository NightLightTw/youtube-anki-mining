# 逐卡稽核

管線做完卡片後，逐張檢查與修正的方法。可以自己在 Anki 做，也可以交給 AI agent（Claude Code、Codex 這類）透過 AnkiConnect 做。對話類影片大約一半的卡定義有問題（見 #3），所以這一步目前省不掉。

## 先看整支影片能不能用

建卡時會印「已用 json3 逐字時間戳校正 X/Y 句」。這個比例比的是兩份字幕的文字，不是音檔，所以只當排查線索，最後還是要抽聽確認：

- **接近 100%**：通常字幕是逐字稿，切點也比較準。
- **比例很低**：先懷疑字幕不是逐字稿。抽幾段音檔聽，確認字幕寫的就是實際說的話，再決定要不要修。
- **沒有這行**：這支影片沒有用到逐字時間戳（只有人工字幕、json3 下載或解析失敗，或一句都對不上），切點靠推算，音檔要逐段聽。

兩類影片整批都不能用：

- **英文字幕是改寫版的**：字幕寫 "The leg is not very tasty"，實際說的是 "It's delicious"。例句跟音檔講的是兩件事。
- **中文語音的影片**：英文字幕是從中文翻譯過來的，對不上語音。如果影片只有機器翻譯的英文字幕，`run.sh` 可能會停在「沒有取得可用的英文字幕」；但它不檢查語音是什麼語言，有人工英文字幕的中文影片還是會進到製卡，要自己判斷。

## 每張卡檢查什麼

對照字典裡這個字的**全部**義項，判斷例句用的是哪個意思，不要只看卡上那一條。最常見的問題：

1. **同義詞來自另一個義項**（最常見，管線不會打 tag）。例如 `racket` 定義是球拍，同義詞是噪音那組（babel、blare）；`drone` 定義是無人機，同義詞是懶人。字典沒有對應義項的同義詞就清空，不要硬留。
2. **定義選錯義項**。例如 `browser` 選到「逛商店的人」，例句講的是網頁瀏覽器；`hedge` 選到「用樹籬圍起來」，例句是「說話含糊其辭」。
3. **`: such as` 結尾的半截定義**：刪掉結尾的 `: such as`，確認剩下的文字是完整的定義；不完整的話改用下一個義項。
4. **查不到定義**（`no-definition` tag）：先看同義詞字典有沒有自己的定義。都沒有才自己寫，並且**明確標註是自己寫的**。補上定義後移除 `no-definition`；`sense-uncertain`、`pos-uncertain` 修好後保留。
5. **中文是字面直翻**：`retrieval` 譯成「檢索」，句子講的是記憶「提取」；`condemn` 譯成「譴責」，句子講的是法院「判罪」。
6. **例句雜訊**：刪掉 `um`、`uh`、重複的字；自動字幕拼壞的人名改成通行拼法。

**改例句時保留目標字的 `<b>…</b>`**。卡片上的藍字就是靠這個標記，整句重寫時很容易一起刪掉。

不適合留的卡直接刪：講到一半的殘字（字幕 "this this mod this the the chip" 裡的 `mod`）、人名、還原錯誤的字（`crosse`、`wed`）。

## 檢查音檔

用 whisper 逐段轉寫，跟例句比對。注意 whisper 自己也會錯（見[技術雷區](pitfalls.md#拿-whisper-當尺時的限制)）：

- 專有名詞和技術詞常被聽錯（"engineering" 聽成 "injury"），字幕通常才是對的。
- 開頭多一個字，可能是起音被切掉了，不一定是切太前面。
- 結尾多字時，用 medium 模型再轉一次確認。

## 重切音檔

有 json3 的影片切點幾乎都對；沒有 json3 的人工字幕影片常常偏，多半是結尾吃到下一句。

1. 只對有問題的那幾段處理。抽出該段前後各約 16 秒，用 whisper 加 `word_timestamps` 轉寫，找出句子大概的位置。不要對整支影片跑 `tools/asr_timing.py`，太慢。
2. 把影片轉成 16kHz 單聲道 wav，用 numpy 算 20–40ms 一格的 RMS 音量（dB），在真正的停頓處下刀。不要用 ffmpeg 的 `silencedetect`（有最短靜音長度門檻）。用 `volumedetect` 量某一段的音量時，用 `-t` 指定長度。
3. 可以一次切好幾個候選版本，都丟給 whisper 驗證再挑。
4. 切檔指令：

   ```bash
   ffmpeg -ss <起點> -i <影片> -t <長度> -af aresample=async=1 -acodec libmp3lame -q:a 4 <輸出.mp3>
   ```

5. 切完再聽一次。原始音檔先備份到不會被清掉的地方。
